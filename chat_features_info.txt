[출장 일정 및 일보 자동화 시스템 - 채팅 요청 반영 기록]

이 문서는 사용자의 채팅 요청에 따라 개발 및 변경된 핵심 기능들과 그 작동 방식을 기록한 안내서입니다. 나중에 시스템을 분석하거나 유지보수할 때 참고하실 수 있습니다.

---

### 1. 출장 일정 작성 완료 후 원래 화면(이전 화면)으로 자동 복귀 기능
* **요청 목적**: 일정(출장 계획)을 처음 작성할 때, "일정 작성완료" 버튼을 누르거나 작성 완료 시 메인보드(홈)로만 가는 대신, 일정을 생성하기 시작했던 본래의 화면(예: '일정' 탭)으로 다시 자연스럽게 돌아가도록 개선하기를 희망함.
* **구현 방식**:
  - `tripCreationSource` 상태(State) 변수를 도입하여 사용자가 어떤 화면(홈화면 또는 일정 탭 등)에서 "새 출장 계획" 버튼을 눌렀는지 그 출처 뷰를 기억합니다.
  - 전용 내비게이션 헬퍼 `navigateToCreateTrip(sourceView)`을 추가하여 페이지 전환 시 이전 상태 정보를 안전하게 보관합니다.
  - '일정 작성완료'(`handleSaveTrip`)가 트리거되면, 새로 만들어진 일정이 자동으로 즉시 선택(`setActiveTrip`)되게 설계되고 원래 진입했던 화면(`tripCreationSource`)으로 매끄럽게 되돌아가도록 처리하였습니다.
  - 작성 폼 상단 왼쪽에도 대칭이 되는 '뒤로가기(Back)' 버튼을 추가하여 작성을 취소하고 원래 자리로 안심하고 복귀할 수 있는 안전장치도 함께 마련하였습니다.

### 2. 버튼 명칭 및 UX 통일화
* **요청 목적**: 사용자가 "일정 작성완료를 누르면" 이라고 설명한 내용에 맞추어 실제 화면의 UI 텍스트와 명칭이 직관적으로 어우러지도록 개선.
* **구현 방식**:
  - 기존의 한국어 `"계획 저장"` 다국어 리소스 키(`btn_save_trip`) 명칭을 사용자가 직접 언급한 `"일정 작성완료"`로 직관적으로 교체하였습니다.
  - 동일하게 일본어 리소스도 이에 맞게 `"日程作成完了"`로 보완 설정하였습니다.

### 3. 비회원/게스트(Guest) 상태에서의 안정적 출장 생성 지원
* **요청 목적**: 로그인하지 않은 게스트 환경(anonymous)에서도 테스트가 가능하도록, 세션이 끊겨 있거나 Firebase Auth 사용자 객체가 없을 때도 일정 생성 로직이 즉각 무력하게 반환되는 일을 방지.
* **구현 방식**:
  - `handleSaveTrip` 동작 도중 게스트 상태인 경우 로컬 `useState` 리스트(`upcomingTrips`, `allTrips`) 및 `localStorage` 등을 연쇄적으로 가동하도록 안전장치(Fallback) 처리를 확장하였습니다.
  - 이를 통해 게스트 사용자 환경에서도 화면 먹통 없이 일정 작성이 정상 가동되고 바로 원본 화면으로 부드럽게 복귀합니다.

### 4. 일보 저장 후 메인 보드 복귀 기능 및 Word 내보내기 자동저장 연동
* **요청 목적**: 일보화면에서 워드 다운로드 등을 포함하여 저장 버튼을 누르면 DB로의 완전한 보존과 동시에 관리 대시보드(메인)로 똑똑하게 돌아가도록 가이드.
* **구현 방식**:
  - `handleExportToWord` 함수 작동 시, 단순히 다운로드만 시키는 것이 아니라 일보 문서를 Firestore 데이터베이스에 백그라운드 선(先) 저장 및 업데이트를 가하도록 연결하였습니다.
  - 가입/비가입 및 다운로드 완료 여부 확인 후 `setView(ViewState.HOME)`을 자동으로 순차 전개하여 원래의 메인 대시보드로 안전하게 회귀시킵니다.
  - 성공적으로 처리되었음을 나타내는 직관적인 성공 얼럿(Toast 알림)을 추가하여 처리 신뢰도를 대폭 높였습니다.

### 5. Gemini AI 기능 최적화 및 안정화 (기존 미작동 오류 해결)
* **요청 목적**: 생성 및 분석 목적의 AI 기능(레시트 스캔, 일정 대화형 가공, 자동 일보 리포트 생성) 호출이 비정상 동작하거나 멈추는 오류 현상을 해결.
* **구현 방식**:
  - 기존 코드에서 존재하지 않거나 비활성화된 모델 명칭(`gemini-3-flash-preview`)을 최신 프리미어 표준 모델인 `gemini-3.5-flash`로 완벽 교체하였습니다.
  - Vite 번들링 속성과 맞물려 작동하는 API Key 참조 방식에 이중 안전장치(`process.env.GEMINI_API_KEY || process.env.API_KEY || ""`)를 적용하여 API Client가 올바른 인증 값으로 통신을 시작할 수 있도록 보강 조치하였습니다.

### 6. Firestore 트랜잭션 예외 처리 및 게스트 모드 오류 원천 차단
* **요청 목적**: 비회원(Guest)이거나 오프라인 혹은 DB 권한이 유해한 상태에서 체크인/체크아웃, 영수증 업로드, 리포트 저장, 일정 추가/수정/삭제를 누를 때, Firebase SDK가 예외를 던져 화면이 먹통이 되거나 경고 토스트가 발생하는 심각한 문제를 수정.
* **구현 방식**:
  - `performCheckIn`, `handleCheckOut`, `handleReceiptUpload`, `handleDeleteTrip`, `handleSaveEdit`, `handleDeleteItineraryItem` 등 모든 데이터 변경 로직에 대해, Firebase DB 호출 전 **로컬 React 상태 저장(`setCheckIns`, `setExpenses`, `setUpcomingTrips` 등)**을 즉각 선행하도록 수정하였습니다.
  - 회원 로그인 세션(`authUser`)이 없을 때 불필요하게 Firebase Docs를 조회하여 권한 에러를 발생시키는 일을 사전에 걸러내며, 세션이 있을 때도 Firestore 호출부를 `try-catch`로 원천 감싸서 서버 오류가 프론트엔드 핵심 UI 업데이트를 방해하지 않도록 철저하게 설계하였습니다.
