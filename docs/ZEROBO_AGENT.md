# OpenAI 전환 — 2026-09-28

제로보와 기존 OCR/AI 보고서 API 모두 OpenAI Responses API로 전환했다. 서버 lib/openai.js만 외부 API를 호출하며 OPENAI_API_KEY/OPENAI_MODEL을 사용한다. 기본 모델은 gpt-4.1-mini, 환경변수로 변경 가능하다. 프런트 geminiService.ts 파일명/레거시 요청 형식은 호환성을 위해 남아 있으나 서버에서 Google API를 호출하지 않는다.

제로보는 strict JSON Schema로 허용한 작업만 받아 서버에서 재검증한다. 기존 OCR/일정 JSON 요청도 strict schema로 변환하고 배열 결과는 원래 배열 형태로 복원한다. 이미지 입력 지원. 거절, 미완성 응답, 잘못된 JSON/작업, 인증·한도·타임아웃은 성공 처리하지 않는다. store:false를 사용하며 이는 API의 모든 로그/보관이 없다는 뜻은 아니다.

OPENAI_API_KEY는 현재 서버에 미설정이다. 본인 프로젝트 키를 서버 환경에 등록해야 실제 모델 테스트가 가능하다. 키를 채팅에 보내거나 VITE 변수에 넣지 않는다. 모델 응답 시험 없이 품질·계정 모델 접근 권한을 보장하지 않는다.

# 제로보 서버 에이전트 — 2026-09-28

## 현재 구현과 연결 상태

AWS `18.177.154.126`에 `/api/agent/messages`를 배포했다. 프런트는 모델 응답을 직접 저장하지 않고 이 API를 호출한다. 서버가 사용자 의도를 분류하고 권한·입력 검증 후 작업을 실행한다.

**실제 OpenAI API 키, 장소 검색 제공자, 메일 서비스는 아직 미설정이다.** 따라서 자연어로 업무를 실행하는 실사용은 AI 키 설정 후 검증해야 한다. 테스트에서 모델·장소 제공자를 대체한 것은 API/DB 실행 로직 검증이며 실제 AI 품질 검증이 아니다. 가짜 AI 응답으로 성공을 표시하지 않는다.

## 동작

- `clarify`: 날짜·시간·대상 등 부족한 정보를 질문한다.
- `list_trips`: 본인 출장 조회. 회사 전체 조회는 사장만 가능하다. 최근 출장 최대 50건을 대상으로 한다.
- `create_event`: 날짜·시간·제목·장소로 새 출장의 일정 1개를 생성하거나 본인 출장에 추가한다. 장소 후보를 조회하여 사용자가 선택한 좌표만 사용한다. 모델 좌표는 받지 않는다.
- `update_event`: 본인 출장의 특정 일정 시간·날짜·제목·장소를 변경한다. 기존 출장 기간 밖이면 오류로 안내한다. 다른 사람의 출장 수정은 사장도 불가하다.
- `write_report`: 해당 날짜의 실제 체크인·경비와 예정 일정을 구분하여 일보를 생성한다. 미등록 방문/회의 성과는 만들지 않는다. 기존 수기 보고서를 덮어쓰지 않고 AGENT_REPORTS에 저장한다.
- `send_report`: 미연결 안내만 반환한다. 실제 이메일 발송 및 자동 연속 실행은 미구현이다.
- `/api/agent/reports`: 본인이 저장한 최근 일보 20건 조회. 대화창의 ‘저장된 일보 보기’로 확인한다.
- `/api/agent/status`: AI/장소/메일 준비 상태만 반환하며 키는 반환하지 않는다.

## 요청/DB

POST /api/agent/messages JSON: `requestId`, `conversationId`, `message`, `language`, 선택적으로 `activeTripId`, `choice:{requestId,index}`.

USER_ID·COMPANY_CODE는 인증 세션에서 결정한다. 모델의 SQL/URL/역할 변경/삭제 작업은 실행하지 않는다. 모델에 최근 본인 출장 50건과 최근 대화 8건을 제공하며 좌표·비밀번호·경비 원본 이미지 등은 전달하지 않는다. 상대 날짜는 Asia/Tokyo 기준이다.

AGENT_REQUESTS에 사용자/요청 ID 복합 PK, 회사, 대화 ID, 입력 해시, 사용자 메시지, 처리 결과를 저장한다. 사용자 행 잠금으로 중복 요청을 직렬화하고 업무 변경과 결과 기록을 한 트랜잭션으로 커밋한다. 같은 ID·같은 입력 재시도는 이전 결과를 반환한다. 같은 ID·다른 입력은409다. 장소 후보 선택은 마지막 대화의 후보만 허용하며 15분 후 만료된다.

프런트는 응답 불명확 시 같은 요청 ID로 재시도한다. 대화창을 닫아도 진행 중 작업은 취소되지 않는다. 현재 대화 UI와 재시도 ID는 메모리에 있어 전체 앱 재실행 후 복원되지 않는다. 서버 기록 조회 UI/보관 기간 정책은 후속 작업이다.

AGENT_REPORTS는 일보 날짜·내용·사용자·출장·회사·생성 시각을 보관한다. 세션/업무 데이터와 별도 테이블이다.

## 서비스 연결

서버 환경변수로 `OPENAI_API_KEY`, 선택적으로 `OPENAI_MODEL`(기본 gpt-4.1-mini)을 설정한다. 키를 프런트 VITE 변수, localStorage, Git 또는 채팅에 넣지 않는다. 운영 배포의 실제 환경 파일/Compose 연결을 확인한 후 컨테이너 환경에 반영하고 다시 실행해야 한다. 단순 docker restart는 변경된 Compose 환경변수를 반영하지 않는다.

장소 어댑터는 HTTPS Nominatim 호환 검색 서버를 받는다: `O1BO_GEOCODER_URL`, `O1BO_GEOCODER_USER_AGENT`. 현재 OSM 지도와 호환되며, 명시적인 검색 요청만 처리하고 타이핑 자동완성에는 사용하지 않는다. 단일 프로세스 기준 요청 간격1.1초, 최대5개 후보, 일본 검색이다. 공용 서버 사용 시 사용정책·연락 가능한 User-Agent·공유 캐시·다중 인스턴스 전역 제한 등을 준비해야 한다. 현재는 연결하지 않았다. Google Places 채택 시 Google 지도와 저장정책에 맞춰 별도 어댑터/지도 교체가 필요하다.

메일은 제공자/발신 주소/수신자 관리/발송 중복 방지와 재시도 상태 모델을 설계한 뒤 연결한다. SES 또는 SMTP 중 선택 필요. 지금은 발송하지 않는다.
