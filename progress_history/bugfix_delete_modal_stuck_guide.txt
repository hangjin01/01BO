버그 수정 내역: 출장 일정/계획 삭제 시 "삭제 중..." 상태에서 멈춤 및 취소 불가 버그 해결
========================================================================

작성일시: 2026-05-29 (UTC)
대상 파일: /App.tsx

1. 현상 및 원인 분석
------------------------------------------------------------------------
- 사용자가 일정(itinerary)이나 출장 계획(trip)을 삭제하려고 할 때, 커스텀 확인 모달(Confirm Modal)이 나타납니다.
- 기존 코드에서는 취소(Cancel) 버튼과 삭제(Confirm) 버튼 모두에 `disabled={loading}` 속성이 부여되어 있었습니다.
- 또한, 삭제 버튼의 텍스트가 `{loading ? '삭제 중...' : '삭제'}` 형태로 표시되도록 설계되어 있었습니다.
- 이로 인해 아래와 같은 치명적인 문제가 발생했습니다:
  1) 로그인 시 자동으로 수행되는 백그라운드 데이터 정리 연동 작업 등으로 인해 전역 로딩(`loading`) 상태가 `true`가 되거나, 혹은 삭제를 누른 즉시 전역 로딩 상태가 `true`로 바뀔 때, 취소 버튼이 비활성화(`disabled`)됩니다.
  2) 이에 따라 사용자가 취소("취소") 버튼을 눌러도 클릭 이벤트가 발생하지 않아 모달 창을 닫을 수 없는 상태("Escapeless State")에 갇히게 되었습니다.
  3) 모달의 삭제 버튼 또한 전역 로딩 중일 때 "삭제 중..."으로 텍스트가 변하며 비활성화되어 더 이상 동작을 진행할 수 없게 되었습니다.

2. 해결 방식 (수정 사항 상세)
------------------------------------------------------------------------
- 모달 내부 버튼들의 상태를 전역 `loading` 플래그의 강제 동기화로부터 분리하였습니다.
- 버튼 동작이 어떠한 복합적인 비동기 상태나 백그라운드 작업 수행으로 인해 멈추지 않도록 아래와 같이 개편했습니다:

  [취소 버튼 개선]
  - `disabled={loading}` 속성을 완전히 제거하여, 어떠한 로딩 상황에서도 항상 '취소(돌아가기)' 동작을 수행할 수 있게 조치했습니다.
  - 취소 클릭 시 `setConfirmModal(null)` 뿐만 아니라 `setLoading(false)`를 함께 호출하여 혹시라도 백그라운드에서 꼬여서 굳어있던 로딩 상태가 복구되어 다른 연계 화면을 정상 이용할 수 있도록 예외 보루를 구축했습니다.

  [삭제(확인) 버튼 개선]
  - 삭제를 클릭한 직후, React 렌더링 배칭(batching)으로 인해 모달이 뒤늦게 닫히거나 멈춰있지 않고, 즉시 렌더링 스택에서 완전히 제거되도록 `setConfirmModal(null)`을 먼저 확실하게 호출해 모달 창을 화면에서 정리합니다.
  - 그 뒤 호출되는 비동기 삭제 동작(`onConfirm`)을 안전하게 `try-catch-finally` 구조로 감싸 예외가 발생하더라도 전역 로딩 플래그가 무한히 `true`로 남지 않고 반드시 `setLoading(false)`를 통해 정상 초기화되도록 수정하였습니다.
  - 전역 `loading`에 의해 버튼 자체가 "삭제 중..."으로 고착화되는 혼란을 막기 위해 버튼 텍스트를 고정적인 "삭제" / "削除" 로 간결하고 직관적이게 유지하되, 전체적인 시각 피드백은 모달이 즉각 닫힘으로써 훨씬 부드럽게 완료되도록 UI 환경을 연출했습니다.

------------------------------------------------------------------------
위 수정으로 인해 사용자가 삭제 확인창에서 절대 고립되지 않으며, 언제든지 안전하게 이탈 및 정상 작동이 가능합니다.
